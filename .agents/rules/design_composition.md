# DESIGN COMPOSITION RULES

LIFE OS MUST NOT use one universal page template.

Every major section must have its own composition.

Do NOT create:

Sidebar
+
Page heading
+
3 cards
+
Chart
+
Recent activity

for every page.

That pattern is forbidden.

Instead, every screen should behave like a different
piece of software inside the same operating system.

TODAY
= command/control workspace

TASKS
= task queue / work manager

HABITS
= calendar-like tracking matrix

WEEK
= operational planning board

LOG
= chronological system terminal

SLEEP
= quiet monitoring instrument

FOCUS
= dedicated full-screen machine/timer

SYSTEM
= diagnostic/control panel

Each screen should have a different visual rhythm,
layout density and hierarchy while sharing the same
LIFE OS design language.

## NO CARD GRID DEFAULT

Cards are NOT the default container.

Prefer:

- bordered sections
- horizontal rules
- toolbars
- windows
- tables
- lists
- grids
- command areas
- terminal-like output
- tabs
- status strips
- drawers
- overlays
- inline controls

Use a card only when a card is genuinely the best
representation of the information.

Never create cards simply because the framework makes
cards easy.

## VISUAL HIERARCHY

The interface should have:

PRIMARY
→ what the user needs to operate right now

SECONDARY
→ supporting information

TERTIARY
→ metadata/system information

The user should immediately understand:

1. What needs to be done
2. What is currently happening
3. What has already happened
4. What state the system is in

Do not make every piece of information equally loud.

## DENSITY

LIFE OS should be information-dense.

However, density must be intentional.

Use:

- compact rows
- small labels
- separators
- grouped information
- toolbars
- narrow metadata columns
- status indicators

Avoid huge empty spaces created only to make the
interface look "modern".

## IMPERFECTION RULE

The interface may contain controlled imperfections:

- slightly irregular borders
- hand-drawn symbols
- pixel offsets
- rough separators
- asymmetric compositions
- occasional texture

But these imperfections must be deliberate.

DO NOT randomly distort text or controls.

Usability always wins.

## REAL SOFTWARE RULE

The interface should look like an application someone
could actually use for several hours.

Do not turn the entire UI into an art piece.

The retro aesthetic is the interface language,
not a filter placed over a normal dashboard.
